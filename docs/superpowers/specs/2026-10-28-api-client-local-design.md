# API Client 本地功能补齐与完整迁移设计

状态：待用户批准；尚未开始实现。

## 已确认的目标

用户主要在本机使用，希望补齐与 Postman 相近的客户端能力。已选择方案 A：继续沿用现有插件和 Postman 运行时，增加兼容模式、OAuth/高级鉴权、OpenAPI/HAR 导入、响应预览、Cookie 管理、GraphQL、SSE/WebSocket/gRPC/MQTT 等本地调试，以及完整加密迁移。暂不建设 Mock、定时监控、文档平台或团队同步。

用户已明确选择两种导出并存：密码加密的完整备份，以及不包含密钥的普通导出。完整备份包含 Token、密码、Cookie 和证书私钥。

## 现有实现与约束

- 仓库 `plugins/codex-api-client`，当前版本 0.2.1；React + MCP Apps，Node 后端、SQLite、macOS Keychain。
- HTTP 执行使用 postman-runtime、postman-collection 和独立子进程。保留这些依赖和已有集合数据格式，不重写 HTTP 执行器。
- 当前工作区格式 v1 只包含集合、环境、全局变量与脚本。敏感值清空，不包含设置、Cookie、附件及证书文件。
- 当前 MCP 工具和界面共用 ApiService；新增能力也必须同时更新工具契约、服务、界面、测试及文档。
- MCP Apps 前端不能直接访问外部网络；协议连接和 OAuth 由后端管理。
- 仓库其他插件有用户未提交改动；仅修改 API Client 及本设计对应文档，在隔离开发分支工作。不覆盖安装缓存，不递增版本、不发布或推送，提供独立数据目录的本地预览。
- 上轮发现文件夹变量会覆盖数据变量；普通 Postman 集合不得受到此扩展影响。

## Approaches

### A：扩展现有本地客户端（用户已选择）

沿用现有集合、运行时、存储和 UI。HTTP 类能力接现有执行链；长连接和其他协议使用独立适配器；迁移升级为带附件清单的版本化归档。优点是保留已有数据和脚本语义，减少重复执行器；代价是协议会话与归档事务需新增完整生命周期管理。

### B：本地 API 平台

在 A 之外再增加 Mock 服务、定时任务与文档生成。可覆盖更多平台能力，但引入常驻服务、调度和发布模型。用户已明确暂不纳入。

不采用重做客户端或直接嵌入 Postman 应用的方式：现有运行时和编辑器可复用，用户数据也应继续保存在当前插件内。

## 功能范围与行为

### 1. Postman 兼容与集合保真

- 增加明确的严格 Postman 模式与文件夹变量扩展开关。标准集合默认严格模式，local > data > environment > collection > global。
- 为既有包含文件夹变量的集合保留原行为并标注扩展，不静默改变已有请求。迁移后可由用户切换模式；扩展模式的覆盖规则明确显示。
- 导入、编辑、保存、导出保留未编辑字段、脚本、请求 ID、认证继承和 body 元信息。
- 单次 Send 不执行 Runner 的后续跳转；集合运行遵循 setNextRequest 等现有语义。
- 不支持或无效的配置必须明确报错，不能静默忽略认证、协议或导入字段。兼容目标是范围内的可验证行为，不承诺与 Postman 全平台等价。

### 2. 鉴权与网络设置

- 在 UI 接入运行时现有的 Digest、OAuth 1.0、OAuth 2.0 Bearer、AWS Signature、Hawk、NTLM、EdgeGrid、JWT/ASAP 等适用 authorizer；具体字段与已安装运行时的 schema 对齐。
- OAuth 2.0 包含授权码 + PKCE、客户端凭据、刷新令牌。授权码通过系统浏览器和短期回环回调完成；校验 state、PKCE、回调路径、过期时间，结束或取消即关闭监听器。刷新不隐式改变其他环境。
- Token、client secret、私钥等保存于 Keychain；界面和模型结果不返回明文密钥。OAuth 的 URL、日志与错误不泄露 code、token 或密码。
- 保留全局设置，并增加请求级超时、TLS、重定向覆盖；界面明确显示继承来源。
- 支持带凭据 HTTP 代理和代理绕过规则；凭据进入 Keychain。沿用现有 CA/mTLS 配置。

### 3. 导入

- 增加 OpenAPI 3.x/Swagger 2.0（JSON/YAML）与 HAR 文件导入，使用成熟转换器；预览请求数量、服务器地址、认证、未支持项后再写入。
- OpenAPI 导入只读取用户选择的文件；不自动获取远程 `$ref` 或运行任何脚本。无法解析的外部引用需明确提示并允许用户补充本地文件。
- 扩展常用 cURL 参数解析，保持不执行 shell 的原则；对于不能保真的选项拒绝或明确告警。
- 保持 Collection v2.1、环境 JSON 与工作区 v1 兼容。导入本身不发送请求。

### 4. 响应与 Cookie

- 按 Content-Type 提供 JSON/XML/文本、图片、HTML、PDF 预览和下载；保留原始字节与搜索。
- HTML/pm.visualizer 放入无同源权限、默认无外部网络的隔离 iframe；不获取主界面令牌、不执行任意本机代码。PDF 如宿主不支持嵌入，则显示明确的本地打开/下载入口。
- Cookie 改为按域管理的结构化界面，编辑 path、expiry、Secure、HttpOnly、SameSite，支持筛选、删除和清空所选域。Cookie 值不进入模型可见结果。
- 扩展 pm.execution.runRequest 的工作区内请求查找与执行，限制递归、深度和总时长；同一运行内继承变量并正确取消。UI 密钥存储继续使用 Keychain，不兼容云 Vault 或任意云脚本包。

### 5. 协议客户端

- GraphQL：查询、变量、operationName、响应；显式触发 schema introspection 与补全，不能打开页面即自动访问目标。
- SSE：实时事件流，event/id/data/retry 展示、取消和重连控制；不再等待连接关闭才展示。
- WebSocket：连接、发送文本/二进制、消息列表、关闭；Socket.IO 作为独立协议入口，避免误当作普通 WebSocket。
- gRPC：用户选择 proto/依赖文件或明确请求 reflection；提供方法选择、JSON 请求编辑、一元调用以及客户端/服务端/双向流、TLS/mTLS 和 metadata。
- MQTT：连接配置、认证/TLS、订阅/取消订阅、发布、QoS 与 retained 消息显示；导入后不自动连接或重订阅。
- MCP 调试：明确连接 HTTP/SSE 服务，列出能力、执行用户选择的工具、查看资源和提示。默认不引入任意本机 stdio 进程启动；如未来需要，作为独立授权范围。
- 每种协议的配置存入集合的版本化扩展字段；普通 HTTP 仍可导出标准 Postman。不能表达的协议不得伪装成有效 HTTP 集合，导出时明确说明。

### 6. 会话生命周期

- 长连接由后端协议会话服务统一管理，分配 session ID，限定消息数量与字节数，以游标分页获取事件，提供连接中/已连接/关闭中/已关闭/失败状态。
- 切换标签不丢连接；关闭请求标签、主动断开、取消、服务退出时清理对应资源。服务重启不自动恢复网络连接。
- 各协议运行与 HTTP Run 区分；各自有连接/操作超时、取消与有界重试。不能无限缓存消息或在失败后无限重连。
- 错误与日志经过密钥脱敏。设置合理的并发与消息限制，具体默认值由实现者根据集成测试确定并记录。
- 本轮 HTTP/GraphQL 使用现有前置/响应脚本、断言与集合 Runner。SSE、WebSocket/Socket.IO、gRPC、MQTT、MCP 提供交互调试、保存配置及事件记录，不支持跨协议 Runner 或逐消息执行 pm.* 脚本；界面必须明确展示此范围。这是实现者提出的边界，需随本设计一起批准，不能宣称其他协议已具有完整 HTTP 脚本能力。

## 完整工作区迁移

### 普通导出

- 继续提供不含密钥的可分享导出，保留 API、目录、脚本、环境、全局变量和可迁移设置。
- Cookie 只包含非敏感属性或明确排除其值；证书私钥、敏感变量、认证秘密与代理密码均排除；不携带 Keychain secretRef。
- 明确列出排除项与需要重新提供的文件。不能把硬编码认证密码漏入普通导出；对确定的认证秘密字段统一处理。

### 密码加密完整备份

- 版本化归档包含：全部 API/协议配置、目录、各级脚本、环境、全局变量、网络与 UI 设置、Cookie、被引用的附件/CA/客户端证书/私钥、所有存储的凭据。
- 包含用户显式选择的运行历史；默认不包含大量响应历史。活动连接、进行中的 Run 与临时 OAuth 状态不迁移。
- 使用 Node crypto 的 scrypt 派生密钥与 AES-256-GCM 加密整个归档，每次随机 salt/nonce。校验归档版本、KDF 参数范围、认证标签、大小与完整性，错误密码和篡改均失败。
- 密码通过 UI 专用工具提交，不保存在集合/设置/日志/报告中；敏感导入导出工具只对 App 可见，不暴露给模型。返回加密归档或预览摘要，不返回解密后的密钥集合。
- 归档文件使用随机内部 ID 和摘要，不将原绝对路径当作写入目的地。仅打包当前请求/设置引用且用户允许读取的文件，不扫描整盘或任意路径。
- 按传输限制分块上传/下载归档，服务端暂存文件和会话均有过期清理；避免把大归档一次塞入 MCP JSON。设置总归档、单文件、文件数与解压大小限制，并在 UI 展示。

### 恢复

- 解密、版本检查、文件完整性和内容校验完成后，先显示集合/环境/凭据/Cookie/附件/设置数量以及冲突预览。
- 默认合并为新增副本，保留请求内部 ID 和脚本跳转关系；显式选择替换时，先创建可恢复快照，不能静默覆盖本机集合。
- 全局变量同名冲突默认保留本机值；Cookie 按 domain/path/key 标识冲突并默认保留本机值；全局网络与 UI 设置默认不覆盖。预览逐项显示保留/恢复的差异，用户可明确选择备份值。不能声称默认合并后必然复现源电脑行为；存在冲突时标明受影响配置。选择整工作区恢复时，备份覆盖上述单例，恢复前快照覆盖集合、环境、globals、settings、cookies、引用文件及对应凭据，失败整体回滚。
- 环境、集合外部引用和当前选中环境需要建立 ID 映射。请求内嵌的原路径改写为目标插件管理目录中的新路径。
- 仅恢复允许迁移的设置字段，不复制任意 filesystem allowedFiles 白名单或源机器环境变量；由导入文件生成最小白名单。
- 密钥写入目标 Keychain，重新生成 secretRef。附件先进入私有 staging 目录；全部验证后与数据库批量事务提交。失败时清理本轮新建文件和密钥，保留已有内容；中断后下次启动清理未提交 staging。
- 导入不执行脚本、不发送请求、不连接任何协议或启动外部程序。
- 继续支持旧 v1 备份，升级不覆盖既有数据目录。需要持久化的 UI 设置从零散 localStorage 整理为显式白名单，保留旧值迁移。

## 实施顺序与验证

分阶段实施同一已确认范围，不把阶段结束当成全部完成：

1. 兼容设置与完整迁移基础，含加密、文件、Keychain、回滚及 v1 回归。
2. OpenAPI/HAR、鉴权、请求设置、Cookie 与响应预览。
3. GraphQL、SSE、WebSocket/Socket.IO。
4. gRPC、MQTT、MCP 调试及跨协议备份恢复。
5. 全量构建、MCP 契约检查、核心功能与 UI 回归、独立本地预览。

验证均用合成凭据与隔离数据目录；不执行用户已有真实集合。重要验收点：

- 同一合成集合在插件与官方 Postman 运行时下的请求、脚本和变量结果一致；区分此验证与完整 Postman 桌面端差分。
- 完整备份跨两个临时目录恢复，真实本地请求可用、凭据不丢失、路径重映射正确；错误密码、篡改、超限、危险路径、事务失败均无部分覆盖。
- 普通导出不含已标记或结构明确的认证秘密、Cookie 值、私钥、secretRef。无法可靠识别的脚本硬编码秘密在导出前提示用户检查。
- OAuth 使用本地授权服务器模拟授权码、PKCE、state 失败、刷新、取消和过期。
- 各协议使用本地 fixture 服务，验证发送/接收、流式顺序、取消、断线、错误、资源回收和归档恢复。
- 预览内容隔离，无法读取宿主凭据或自动联网。
- 使用现有测试结构扩展用例，不为测试引入无人使用的生产接口。

## 留给实现者的决定

复用已有 helper 与布局；成熟转换器/协议库的确切版本在实现前核实官方文档并固定锁文件。模块划分、归档后缀、默认大小限制、消息分页大小、局部 UI 排版由实现者决定并用验证支撑。不得因此扩大产品范围、放宽秘密保护或省略已确认协议。
