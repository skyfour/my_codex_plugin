# 三个插件的界面与操作复核

本轮检查覆盖 API 调试台、任务看板和本地代码审查的现有页面、弹窗及主要状态。目标是让使用场景和参照产品一致，并验证用户能真正操作控件。检查不等于复制参照产品的全部商业功能。

## 场景与界面对应

| 插件 | 参照与交互原则 | 当前流程 |
| --- | --- | --- |
| API Client | [Postman 请求编辑器](https://learning.postman.com/v11/docs/getting-started/basics/postman-elements)：集合组织请求，环境影响变量，编辑区集中参数、认证、请求头、请求体和脚本 | 左侧集合/文件夹树 → 多请求标签 → 方法、URL、发送 → 请求/响应上下区域；集合、文件夹、请求的运行选项明确区分对象 |
| API Client | [Postman Collection Runner](https://learning.postman.com/latest-v-12/docs/tests-and-scripts/running-collections/intro-to-collection-runs)：按目标范围顺序运行，支持数据与停止条件 | 选择集合或文件夹 → 确认名称、迭代、间隔、JSON/CSV、失败停止 → 执行或取消 → 每个响应、断言、日志和报告 |
| 任务看板 | [Jira 看板筛选](https://support.atlassian.com/jira-software-cloud/docs/filter-work-items/)与[卡片详情](https://support.atlassian.com/jira-software-cloud/docs/create-edit-and-delete-work-items-on-the-board/)：筛选作用于看板，点卡片查看详情，状态依照工作流流转 | 看板顶部组合筛选 → 状态泳道与拖放 → 任务详情 → 本地状态、TAPD 来源、提交关联及会话；设置独立管理泳道、流转、数据源 |
| 代码审查 | [Sublime Merge 工作流](https://www.sublimemerge.com/docs/getting_started)：项目和分支上下文明确，文件/改动块附近提供 Stage，Pull/Push 使用主按钮和选项入口 | 多项目标签 → 当前分支与同步工具栏 → 工作区/提交历史/审查记录 → 文件列表 → 常驻提交区与差异；All、文件、Hunk 各自具有操作入口 |

保留各插件的独立应用服务与数据边界。任务看板对外提供提交上下文；代码审查通过公开的提供方接口获取任务与关键字，本轮没有在审查插件新增 TAPD 适配器或凭据读取。

## 视觉评估

下列等级是基于真实浏览器截图与操作的启发式评估，不是性能测量：A 表示细节成熟，B 表示专业可用，C 表示有明显一致性缺口，D 表示问题影响操作。本轮总体设计由 C+ 提升至 B；模板化程度维持 B。三者均采用工具工作区的排布，保留系统字体和紧凑控件；没有加入不服务操作的装饰与动画。

| 维度 | 调整前 → 调整后 | 依据 |
| --- | --- | --- |
| 视觉层级（15%） | B → B | 集合/看板/项目上下文和主要操作位置明确 |
| 字体（15%） | B → B | 项目、分支、代码和任务描述各自采用适合内容的排版 |
| 间距与布局（15%） | C → B | 解决固定最小高度造成的裁切，保留桌面密度 |
| 色彩与对比（10%） | C → B | 会话弹窗与主界面的主题一致，取消/关闭文字可辨 |
| 交互状态（10%） | D → B | 保存与勾选后恢复焦点，弹窗隔离全局快捷键 |
| 响应式（10%） | C → B | 矮窗口可正常滚动到控件，不依赖程序滚动隐藏容器 |
| 文案（10%） | B → B | 运行对象与分支比较语义更明确 |
| 模板化程度（5%） | B → B | 界面围绕编辑、任务和代码流程组织 |
| 动效（5%） | B → B | 维持工具界面的稳定布局 |
| 性能感受（5%） | B → B | 已有忙碌、失败恢复与取消反馈，本轮未做性能基准 |

自动设计检测器未运行；覆盖证据来自截图、原生一致性审查和 Chrome 操作。八组问题均以行为或布局回归验证，未保留仅凭源码判断的“已修复”结论。

## 本轮修正

| 问题 | 修正 | 回归证据 |
| --- | --- | --- |
| API 文件夹的按钮及弹窗仍称“运行集合”；请求的入口也使用集合名称 | 按集合、文件夹、请求显示运行名称，实际运行目标仍由 itemId 决定 | `ui-audit.spec.ts` 检查三个名称，并用无关根请求和另一文件夹证明目标范围 |
| API 高度不足 600px 时应用超出窗口，响应按钮依赖程序滚动隐藏父容器才能到达 | 应用遵循实际窗口高度；矮窗口中请求和响应区域具有正常滚动路径 | 620×500 下真实发送、控件命中及隐藏滚动检查 |
| 看板暗色模式中会话弹窗仍为白底，取消和关闭文字对比不足 | 会话弹窗、列表、提示和代码块使用统一主题变量 | 暗色会话截图、完整会话流程与不同宽度控件检查 |
| 关闭“新建会话”后错误聚焦绑定入口，重绘再次丢失焦点 | 根据弹窗类型恢复到实际入口，并保留入口身份 | Escape 关闭后验证焦点位于“新建会话” |
| 数据源保存、候选键盘勾选和状态表单重绘丢失焦点 | 使用稳定控件身份；工作流身份包含来源泳道，防止不同规则的相同目标冲突 | Enter 保存后保持姓名输入焦点；Space 勾选保持候选焦点；工作流 key 唯一与焦点测试 |
| Review 左侧“分支”点击其实是比较，容易误认为切换 | 可见标题改为“分支比较”；顶部仍为切换/创建入口 | 分支标题与 Git 切换真实执行测试 |
| Git 弹窗打开时 ⌘/Ctrl+O、P、R 仍触发底层操作 | 弹窗期间隔离全局项目快捷键，保留原生 Escape | 检查目录选择器次数、全部工具调用次数、弹窗数量 |
| Review 矮窗口中状态栏超出窗口，差异操作被隐藏容器裁切 | 高度跟随宿主；短窗口的提交、差异和文件区域允许正常滚动 | 820×600、620×500、390×700 的逐控件命中及隐藏滚动检查 |

## 验证命令与证据

```sh
npm test
npm run check
npm run test:ui
```

`test:ui` 先构建 API 源码，再运行其完整 Playwright 套件，然后执行任务看板及 Review 的原生 MCP 宿主测试。单独执行可用 `test:api-ui`、`test:task-panel-ui`、`test:local-review-ui`。

新增检查的 JSON 与截图默认写入 `/tmp/codex-plugin-ui-audit`，可通过 `UI_AUDIT_DIR` 指定持久目录。API 检查 1440×950、820×600、620×500；看板和 Review 另检查 390×700。现有套件还覆盖 1024px 和更宽桌面、深浅主题、错误及并发状态。

2026-10-15 最终验证：137 项 Node 测试、45 项 API 浏览器用例和两个真实 stdio MCP 检查通过；看板原有三组脚本及新增 45 组工作流/控件检查通过；Review 原有四组脚本及新增 42 组检查通过。新增审计分别执行 API 837 次、看板 406 次、Review 258 次指针可操作性检查，这些是跨状态与尺寸的检查次数，不是唯一按钮数量。

本机归档位于 `exports/codex-plugin-ui-review-2026-10-15/`：`results/` 保存最终 JSON，`logs/` 保存完整命令输出，`screenshots/` 保存页面与实际旧版/新版对照，`diagnostics/` 保留修复过程中的失败证据。聚合运行曾因测试定位到禁用候选而中止，改正定位后分别重跑看板和 Review 的完整入口通过；没有隐藏失败或用重试次数代替成功断言。对照截图 `task-dialog-before/after.png`、`review-short-before/after.png` 使用 `bc6b7e1` 与当前界面源码、相同合成数据生成。

所有测试使用临时数据库、合成令牌/任务、localhost API、临时 Git 工作区与本地 bare remote。浏览器确实点击、输入、发送与执行 Git；TAPD 和 Codex 会话提供方在集成测试中使用合成边界，不访问真实账户。这轮不能代替另一台电脑上宿主 UI 的手工验证、操作系统目录选择器交互或公网 TAPD/SSH 的连通性验证。

本轮仅修改开发分支源码与回归入口，沿用既有版本。正式发布时再统一递增版本、合并和更新安装缓存。
