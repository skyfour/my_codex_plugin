# 审阅区：Summary 与文件标签

本轮先只读观察本机 Sublime Merge 的 Details 区，再核对官方的[工作区与提交详情](https://www.sublimemerge.com/docs/getting_started)、[差异上下文](https://www.sublimemerge.com/docs/diff_context)及[文件、改动块控件结构](https://www.sublimemerge.com/docs/themes)。此前主要参照了按钮位置，没有对齐审阅流程：每次只展示一个文件，未暂存和暂存内容混在一个查看范围里，单文件全局状态也承担了局部操作上下文。

## 当前交互

| 区域 | 行为 |
| --- | --- |
| Summary | 默认连续展示整批变更，工作区分为 Working Directory / 未暂存与 Staged Files / 已暂存。上下滚动可审阅多个文件，无需反复选文件。 |
| 全屏审阅 | 差异标签右侧提供入口，隐藏项目与提交导航，让审阅区占满插件视窗；保留标签和状态栏，按钮或 Esc 退出。弹窗先处理 Esc，后台加载时仍可退出。 |
| 文件标签 | 每个文件按所属分区拥有标签，同一部分暂存文件可分别打开 M、S 标签。单独查看时显示该范围的所有改动块及对应操作；进入历史或返回工作区时回到 Summary。 |
| 文件头 | 可折叠该文件；未暂存文件提供 Discard、Stage，已暂存文件提供 Unstage。操作捕获该文件与分区，完成后定位到更新后的文件。 |
| 改动块头 | 提供本块 Stage/Unstage/Discard Hunk 与上下文切换；行号是位置说明，不再暴露原始 `@@` 语法。 |
| 部分暂存 | 未暂存区比较暂存区与磁盘，已暂存区比较 HEAD 与暂存区。两个差异各自独立，不能拿合并后的差异去执行局部操作。 |
| 提交区 | 工作区 Summary 中固定在标签下方，滚动代码时保留提交说明、任务关联与提交操作；短窗口限制高度、支持内部滚动。文件头和定位使用实际固定区高度避让，单文件标签、历史及快照不显示提交区。 |
| 行内批注 | 行号旁「＋」打开代码下方编辑器；按旧／新侧和真实行号显示已保存批注，支持删除。Summary 保持连续审阅，全屏沿用同一编辑器。底部汇总提供定位入口，能展开上下文或跳到对应分页。 |
| 历史与快照 | 历史提交连续显示文件差异及提交信息；审查快照沿用同一结构。历史不显示 Git 写操作；已审阅快照提供明确的 Stage 入口，并拒绝内容过期。 |

审阅标记、快照和任务联动继续保留；不提供逐行暂存、鼠标拖动上下文边界或 Git 提交图功能。

## 分支与历史范围

Git 命令栏中央是当前工作分支下拉入口，右侧保留 Fetch / Pull / Push。下拉为锚定的非模态 popover，支持搜索、方向键、Enter 与 Esc，底层审阅仍可操作；不弹出分支确认对话框。选择本地分支直接执行受令牌保护的切换，远端分支在同一面板中选择本地跟踪、改名跟踪或分离 HEAD。新建分支也沿用面板内表单。同名本地分支不会被覆盖，提供显式切换入口。操作失败保留选择和名称，关闭下拉不取消已经开始的 Git 操作；项目切换后旧结果不会回填新项目。Sublime Merge 的[Header 说明](https://www.sublimemerge.com/docs/themes)将当前分支信息放在中央；它的[分支可见性](https://www.sublimemerge.com/blog/sublime-merge-build-1070)与 checkout 是独立操作。本插件按同样区分处理历史范围：

- 当前分支：显示当前 HEAD 可达的历史，包含共同祖先；不是与某个基线比较后只取独有提交。detached HEAD 沿用当前提交；未产生首次提交的分支显示空历史。
- 全部分支：合并本地、远程分支以及当前 HEAD 的历史；排除仅由标签或 stash 引用的提交。
- 选择分支：可搜索并勾选最多 32 个指定分支，共同提交去重。选择只影响历史显示，不 checkout；每个项目分别保存范围。

历史按拓扑顺序显示最多 100 条，分支标签标在各分支 tip，HEAD 单独标记。真正 checkout 后保留历史页并优先选择当前范围内的新 HEAD；纯范围筛选尽量保留已选 SHA，仍可见时不重载差异或丢失草稿，超出范围时选新的可见提交。所选引用被删除后显示提示，可重新选择；外部 checkout 后点击刷新同步，当前正在看快照也会更新仓库元数据。切换到其他 commit 前先保存旧草稿并清除旧文件锚点；相同路径不会把前一份提交的评论带过去，原草稿仍可从原审查记录恢复。分支比较使用完整 refs，分支展示名由完整 symbolic ref 提取，避免同名标签造成消歧错误。

## 模块边界

- `ui/review-surface.mjs`：Summary 状态、文件标签、分区投影、按需加载、局部折叠与共用差异渲染。接收 DTO 与回调，不访问 Git、TAPD、凭据或数据库。
- `ui/app.mjs`：把界面意图转换成现有 MCP 应用服务调用，保存评论、快照与提交草稿；局部操作显式携带文件、范围、fingerprint 或 hunk token。
- `ui/history.mjs`：历史范围与分支多选界面，按项目保存偏好，协调已选提交与空历史状态；不执行 checkout。
- `ui/git-workbench.mjs`：现有 Git 操作与确认窗适配器。Summary 传入自己的操作上下文，确认窗使用目标文件名，不借用全局当前文件。
- 既有 Git/审查领域服务保持职责不变；服务端只增加新 UI 模块的内联装载。

## 状态和性能约束

Summary 使用同一个纵向滚动面。文件头在桌面视图保持可见，窄面板的文件操作允许换行。文件内容接近可视区时读取，最多同时执行三项读取；预览缓存遵循当前总大小设置，每个差异视图一次渲染 500 条展示记录。

缓存归属包括项目、比较范围和快照身份。进入快照时清除实时缓存，防止其他文件显示快照创建前的内容。文件标签中标记已审阅或保存快照时，保存该标签正在显示的比较范围，避免部分暂存文件混入另一侧差异。读取文本后再取得 hunk 信息，并复核文本摘要；读取期间变化的文件要求刷新。实际写操作仍由原服务验证文件 fingerprint、hunk token 与快照内容。

Stage / Unstage 刷新时保留同一比较范围中 fingerprint 未变化的预览与实际 DOM，避免所有文件短暂变成加载占位。Summary 保持原审阅位置：同分区仍有当前文件就保留，移出时由原分区后继或前驱接替；没有邻居时保留滚动位置，不跨区追随同一路径。首次更新文件列表时即恢复锚点，后台提交准备不能覆盖它；滚轮、触摸、点击或键盘输入会取消跟随，包括操作 RPC 尚未返回的情况。单文件完整操作仍跟随同一路径到目标分区，局部操作先保留原侧剩余改动；两侧都没有该文件时回到 Summary。

Summary 与单文件保留各自宿主，只有当前宿主接入可见 DOM。搜索只移除不匹配的卡片，清除搜索后复用已读取内容。布局切换优先重绘视口附近卡片，离屏内容通过同一 IntersectionObserver 更新。完整验证及局限见[流畅性 QA 报告](review-fluency-qa-2026-10-16.md)。

全屏切换只改变布局，不重复读取已加载文件或替换差异 DOM；新进入可视区的文件仍按需读取。保留当前 commit、文件、草稿与审阅标记；按第一条完整可见代码行补偿折行后的纵向位置。关闭折行时补偿展开导致的横向范围压缩，用户在全屏内主动横滚后尊重新位置。到文件首尾时，位置仍受浏览器实际滚动范围限制。

## 批注与草稿

批注沿用现有审查记录的数据结构与版本校验；首次添加时保存当前已展示的比较范围，并用该预览的内容摘要核对，过期时拒绝创建，避免旧行号应用于新代码。Summary 中选未暂存／已暂存的行分别保存该侧快照；不会将两种比较合并。普通目录沿用单文件快照。

编辑器在差异行之间复用同一个表单节点。更新批注只协调附加的批注行，不重新高亮或替换代码表格。首次快照替换实时缓存时承接最新可见文件锚点；用户在等待期间滚动会取消旧行的自动定位和焦点请求，后续加载仍尊重新位置。草稿按项目、范围／快照、文件、旧／新侧及行号分别保存，仅在同一面板会话中恢复；已保存内容随快照持久化。保存期间锁定编辑器，失败保留输入；Markdown／JSON 导出仍使用同一份审查记录。
