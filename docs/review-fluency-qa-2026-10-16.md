# 代码审查 0.5.3：功能与流畅性 QA

本次依据连续审阅体验检查整个插件：操作期间是否保持位置与内容、能否继续导航和输入、后台迟到响应是否覆盖新选择。Git 写入、评论、提交及远程同步均使用合成临时仓库和临时数据库；用户录屏与业务代码没有进入仓库。

## 发现与修复

| 发现 | 修复与长期检查 |
| --- | --- |
| 原有测试只等操作结束，无法发现中途跳动 | 暂存用例按 rAF 帧采样几何位置与 DOM 身份，既检查等待中也检查完成后。 |
| Summary 暂存后追到另一分区 | 保留原分区审阅位置，当前文件移出时由后继或前驱接替；无邻居时保持滚动位置。用户导航优先。 |
| 缓存命中仍整页重算差异与高亮 | 按文件 fingerprint 保留卡片和表格 DOM；Summary / 文件切换、搜索恢复不重复计算或读取。 |
| 布局切换同步重画全部已加载卡片 | 先绘制视口附近内容，离屏缓存通过既有 IntersectionObserver 更新；滚动到时必须显示当前布局。 |
| 慢请求期间后续文件、分类、项目选择被丢弃 | 文件选择使用请求代次与项目身份验证；其他导航保留最后意图。新项目接管时移除旧项目导航，阻止路径跨项目套用。 |
| 提交区和任务目录拖长 Stage 等待 | 代码阅读与 Git 结果先恢复；提交准备后台更新，暂存刷新复用已加载任务目录。旧令牌失效，准备完成前禁提交。 |
| 后台提交区更新覆盖显式审阅锚点 | 复用当前有效锚点，在首次列表更新后、下一帧绘制前恢复位置。 |
| 提交期间允许继续改说明，成功响应会清掉新文字 | 真正执行提交时暂禁编辑说明，完成或失败后恢复；Stage、阅读和任务加载时可输入草稿。 |

这些检查不会放宽原有 Git fingerprint、HEAD/index 校验、写锁、快照一致性或 destructive 操作确认。

## 性能证据

同一台机器、真实 Chrome、40 个各 400 行的合成文件；前后使用相同布局，并给任务上下文加入 800ms 延迟。以下是同场景的一轮诊断测量，不是跨机器性能承诺：

| 指标 | 0.5.2 | 修复后 |
| --- | ---: | ---: |
| Summary Stage 至主交互就绪 | 3177ms | 822ms |
| Summary Stage 至差异稳定 | 5118ms | 1172ms |
| 重复选择当前文件 | 341ms | 78ms |
| Stage 时重复差异计算 / 逐行高亮 | 22 / 17600 | 0 / 0 |

独立的不变缓存回归要求返回 Summary、搜索后清除筛选均为 **0 次重复 diff、0 次高亮、0 次后端预览读取**，并核对同一份 DOM，而非只检查最终文字。

8 个已加载卡片的布局专项从 8 次 diff / 1280 次高亮降为附近 1 次 diff / 160 次高亮；离屏内容滚入后仍须更新为新布局。40×400 行场景的布局重绘长任务从约 669ms 降至约 226ms，仍存在大差异本身的绘制开销。

## 回归命令与证据

最终统一验证：`npm test` 162/162 通过（代码审查自身 55 项）；两个插件的真实 stdio MCP 检查通过；九组代码审查 Chrome 脚本全部通过。其中五组命名检查共 93 项：窗口/控件 42、Summary 17、逐帧暂存 13、性能 7、连续操作 14；另外四组旧脚本的断言全部保留并通过，不把其 assert 数冒充独立用例数。记录的浏览器未捕获异常为 0。

```sh
npm test
npm run check

review_qa_dir=$(mktemp -d)
UI_AUDIT_DIR="$review_qa_dir" CODEX_UI_SCREENSHOT_DIR="$review_qa_dir" npm run test:local-review-ui
```

完整代码审查浏览器套件包含九组脚本。新增与加强的检查分别由以下脚本维护：

- `scripts/check-local-review-stage-selection.mjs`：逐帧源位置、后继/前驱/无邻居、DOM 保留、单文件跟随和手动导航。
- `scripts/check-local-review-performance.mjs`：缓存、搜索、宿主切换、读取恢复与可见区域优先绘制。
- `scripts/check-local-review-fluency.mjs`：真实连续指针操作、受控慢响应、项目隔离、草稿与提交令牌。
- `plugins/codex-local-review/tests/git-commit.test.mjs`：只刷新暂存区时不请求任务 provider，令牌仍随实际 index 改变，参数仍严格验证。

性能门槛使用可重复的 DOM 身份、读取与计算次数，绝对毫秒数只作诊断。内容检查等待实际对应的表格；主交互结束不代表所有离屏懒加载已经完成。失败不能通过减少断言、固定延时或事后拉回目标来掩盖。

运行目录保留 `review-stage-selection-layout.json`、`review-performance-measurements.json`、`review-fluency-results.json`、逐场景结果与合成截图；源码仓库只保存测试与说明。

## 覆盖边界

真实外部 TAPD、SSH 认证、GitHub 网络、用户仓库 hooks 与当前 Codex 桌面宿主的调度没有用合成结果冒充验证。UI 测试运行在真实 Chrome 的原生 MCP 宿主适配中，stdio 另作真实连接检查。

任务关联或提交准备未完成时，相应提交功能仍会等待并显示状态，代码阅读及草稿输入可继续。大型 diff 首次读取、计算和绘制仍有成本。本次防止的是已复现的整页重建、中途位置跳动、丢操作、迟到结果覆盖和草稿丢失，不能保证所有硬件、仓库与外部网络都无卡顿。
