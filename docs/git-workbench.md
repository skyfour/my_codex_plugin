# Git 工作台交互与边界

在已有项目、差异、审阅与提交功能上扩展 Git 工作台，不改变任务看板提供提交上下文的边界。

- 中央分支按钮展开可搜索的非模态下拉，按本地 / 远端分组，支持方向键、Enter、Esc 和外部点击关闭；不遮断底层审阅。直接选择本地分支即可切换，列表内可从当前 HEAD 新建并切换。
- 远端分支在下拉内提供创建本地跟踪分支（名称可改）、切换已有同名本地分支与检出远端提交（分离 HEAD）。不会重写同名本地分支；跟踪创建会设置 upstream。操作等待时可关闭下拉，已开始的操作仍继续，失败后重开保留原选项和名称；新项目不会显示旧项目的错误。
- 分支操作用 Git 正常保护机制，冲突时停止，不强制切换或自动 stash。目标和工作区变化会令执行令牌失效；分支名与远端引用通过结构化参数传入，使用完整引用及参数边界消歧。
- 顶部 Fetch / Pull / Push 提供远程与分支选择。Fetch / Pull 主按钮直接使用当前跟踪目标；缺少明确目标时进入选择界面，Pull / Push 下拉可更改目标，Push 仍需核对确认。Fetch 更新远程引用；Pull 只允许 fast-forward，并保留可安全携带的本地改动；会覆盖文件时由 Git 停止，不自动 stash；Push 展示远程与目标分支、可设置 upstream，不提供 force push。使用系统已有 Git 认证，不在插件保存认证信息。
- 文件层操作包括 Stage / Unstage / Discard；范围层包括 Stage All / Unstage All / Discard All，全部操作独立于文件搜索条件。Discard 仅丢弃未暂存内容，已暂存内容保留；未跟踪普通文件会删除，必须在确认中列出。
- 改动块层提供 Stage Hunk / Unstage Hunk / Discard Hunk，使用 Git 生成的补丁，不接受客户端传入补丁。部分暂存文件在 Summary 中按暂存与未暂存分区分别操作，文件标签也携带各自比较范围；不能对混合的 HEAD → 磁盘差异执行局部操作。
- Discard 与 Push 在执行前展示具体范围 / 目标；所有操作执行前校验预览状态，过期时要求刷新。确认取消不写入。操作完成刷新分支、提交记录、文件、暂存区与提交草稿。
- 历史比较仅展示内容，不显示文件 / 改动块写操作。审查快照保留上一批实现的核对后 Stage 能力；普通 Git 操作回到实时工作区进行。

Git 基础设施提供进程执行、参数隔离和仓库写锁。Git 应用服务分别负责仓库同步 / 分支操作、丢弃工作区与补丁操作；MCP 仅解析 DTO 和调用服务。界面只呈现状态、选择参数和确认结果，不拼接命令。验证使用临时仓库与临时 bare remote，不向用户业务仓库发送提交或改写文件。

分支下拉由 `ui/branch-picker.mjs` 管理，仅发送结构化操作意图；Git 预览与执行仍共用仓库写锁和状态令牌。远端跟踪按有效 fetch refspec 反推唯一来源，不能将本地远端引用的路径后缀当作服务器分支名。目标本地名已有有效 tracking 配置时，预览拒绝并保留配置；创建后再次核对实际 upstream，若钩子或配置写入导致部分完成，会明确提示刷新核对，不自动重置分支。
