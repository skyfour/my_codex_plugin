# 本地代码审查 0.4.1

在 Codex 侧栏打开“本地代码审查”，或输入“打开本地代码审查”。参考 Sublime Merge 的仓库浏览与差异审阅流程，提供本地人工 Review，无需远程仓库。

## 打开与切换项目

- 点击“打开项目…”或 `⌘O`，用 macOS 文件夹窗口选择一个或多个项目。选择 Git 仓库内的子目录也会自动定位仓库根目录。
- 左上角 `＋` 打开内置目录浏览器，可逐层进入文件夹、直接打开当前文件夹，或“查找子目录中的仓库”后勾选批量添加。也支持粘贴 `~/work/project` 路径。
- 顶部项目下拉框在窄面板中也始终可见，左侧保存最近项目，顶部提供可关闭的项目标签，`⌘P` 可搜索项目名称或路径，按 ↑↓ 和 Enter 切换。
- “管理”可固定或移除当前项目，右键项目条目也可管理失效的目录入口；移除不删除源代码或审查记录。重开会恢复上次的项目、所选文件和审查快照。

## 浏览和审查

打开 Git 项目后直接显示未提交改动，不必先创建快照。“工作区”按全部、已暂存、未暂存筛选；文件列表支持搜索。中间“提交历史”浏览最近 100 个本地提交，点击查看相对第一父提交的差异，根提交也可查看；点击左侧分支比较 `HEAD → 分支`。

窄面板默认使用统一差异，宽面板默认并排；手动选择后会保留当前面板的视图偏好。右侧差异按真实新增和删除行对齐，支持并排/统一视图、语法高亮、折行、差异块导航、展开上下文和完整文件。默认仅显示改动周围 3 行上下文；大型差异每页最多 500 个对齐行条目。可用 `Alt+↑/↓` 跳转差异块，`j/k` 切换文件，`⌘R` 刷新。代码源文件始终只读。快捷键不常驻显示在界面上，鼠标悬停对应控件时显示提示。

点击旧或新代码的行号添加备注、问题或阻塞问题，也可标记“已审阅”。首次评论或标记会自动保存当前范围的审查快照；也可手动点击“保存审查快照”。若文件在查看后发生变化，会提示刷新，避免评论落在不同版本上。标签上的 × 只关闭标签，项目仍在最近列表中；可从下拉框重新打开。每个项目独立保存进度；同一面板内切换项目或文件会保留尚未保存的评论草稿。

从“审查记录”打开历史，或点击“返回工作区”查看新改动。快照不会随磁盘变化；对新改动需重新保存审查。导出 Markdown 包含状态和评论，JSON 包含代码快照；下载不可用时可复制文本。

没有 Git 的文件夹可以直接逐层浏览文件，选中文件查看代码并保存单文件审查。二进制文件只显示提示，可标记已审阅。

## 本地数据与限制

数据保存在 `${CODEX_HOME:-~/.codex}/local-review/reviews.sqlite`，可通过 `LOCAL_REVIEW_HOME` 修改目录。升级兼容 0.1 的审查记录并自动生成项目入口。各电脑数据独立，数据库权限 0600，不上传项目路径、代码或评论。

单文件默认上限 5 MiB，一次快照默认上限 50 MiB，最多 300 个文件。顶部“设置”可将单文件设为 1–20 MiB、快照总量设为 10–200 MiB，快照上限至少为单文件上限的两倍。设置保存在本机，重开后保留。超限提示会显示调整入口；单个大文件不阻塞其他文件预览，也不限制 Git 暂存操作。浏览改动按文件懒加载，其他大文件不会阻塞小文件预览。查找仓库最多深入 3 层、访问 1200 个目录、返回 100 个项目；不跟随目录符号链接，达到上限会提示。跨项目符号链接不会读取。

本版对齐项目打开、项目切换、工作区/历史浏览和差异审阅；暂不实现 Git 推送、合并、冲突解决、完整提交关系图、字符级差异或 AI 审查。提交历史展示最近 100 条，审查历史按项目分别展示最近 100 条。

在仓库根目录执行 `node scripts/install.mjs` 安装/升级。验证：`npm test`、`npm run check`、`npm run test:local-review-ui`（需要 Chrome）。

参考：[Sublime Merge 官方入门文档](https://www.sublimemerge.com/docs/getting_started)、[差异上下文](https://www.sublimemerge.com/docs/diff_context)。

0.3.1 合并顶部项目工具栏，统一深浅主题与控件样式；项目、分支及文件名保持单行省略，悬停显示全文。干净工作区隐藏无效差异工具栏，并提供浏览提交历史和刷新入口。

## Stage / Unstage

工作区视图中，右侧提供当前文件的 Stage / Unstage。文件列表可勾选多个文件，再点击 Stage / Unstage 批量操作。“全选可见”只选当前过滤结果；按钮中的数字是本次实际操作的文件数，列表刷新会清空勾选。未暂存列表包含未跟踪的新文件。

Stage 使用 `git add --all -- <所选具体文件>` 暂存当前磁盘内容（含新增、修改、删除）；Unstage 使用 `git restore --staged --source=<当前 HEAD> -- <所选具体文件>` 只还原暂存区，保留工作区文件。无首次提交时仅移除相应 index 条目。暂存后仍可继续编辑文件，两种状态会分别保留。操作后自动刷新；审查快照、历史提交和普通非 Git 文件夹不提供这些写操作。

操作只响应用户在面板的明确点击，使用固定命令与字面文件路径，不接受任意 shell。列表过期、暂存区锁定、未解决冲突或子模块会给出明确反馈；不会自动删除锁文件、解决冲突、提交、推送或修改源文件。

参考：[git add](https://git-scm.com/docs/git-add)、[git restore](https://git-scm.com/docs/git-restore)。

## TAPD 任务联动提交

任务看板的任务详情可调用 TAPD `GET /svn_commits/get_scm_copy_keywords` 获取并缓存完整源码关键字，也可手动保存原文。代码审查工作区顶部的「提交…」读取同一 `TASK_PANEL_HOME`（默认 `$CODEX_HOME/task-panel`）内的本地看板，选择任务后在提交说明下附加完整关键字。两插件只通过现有本地 SQLite 数据联动，无额外服务；审查插件以只读模式打开看板。

提交窗口展示仓库、分支和所有暂存文件，只提交暂存区；未暂存内容保持原状。HEAD、分支或暂存树变化时要求重新核对。支持首次提交，保留正常 Git hooks；拒绝空暂存区、冲突、detached HEAD 及进行中的 merge/rebase/cherry-pick/revert。只创建本地 commit，不 push、不改变 TAPD 状态。TAPD 远端关联仍需项目的源码应用和仓库 Webhook 接入；本地 commit 不代表 TAPD 已收到记录。

## 开发中：工作区常驻提交编辑区

提交编辑区位于工作区差异上方，无需打开弹窗。尚未 Stage 时也可先编辑说明；Stage、Unstage、刷新或切换项目会保留各项目的说明草稿。选择已导入的 TAPD 任务后，审查插件使用任务看板已有的本机凭据直接查询源码关键字，无需到看板逐项获取；说明为空时自动填入任务标题。获取失败保留草稿，显示原处重试入口，获取成功前禁止关联提交。完整 message 和暂存文件可展开预览，提交按钮明确提示暂无暂存改动。历史或审查快照不会显示提交编辑区。

接口原文仅在审查服务内存缓存，任务看板数据库保持只读；提交时核对所选任务关键字。仍要求用户明确点击提交，保留正常 Git hooks、HEAD/分支/暂存树校验，不自动 Stage、push 或修改 TAPD。
