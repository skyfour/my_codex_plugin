# 本地代码审查 0.5.10

在 Codex 侧栏打开“本地代码审查”，或输入“打开本地代码审查”。参考 Sublime Merge 的仓库浏览与差异审阅流程，提供本地人工 Review，无需远程仓库。

## 打开与切换项目

- 点击“打开项目…”或 `⌘O`，用 macOS 文件夹窗口选择一个或多个项目。选择 Git 仓库内的子目录也会自动定位仓库根目录。
- 左上角 `＋` 打开内置目录浏览器，可逐层进入文件夹、直接打开当前文件夹，或“查找子目录中的仓库”后勾选批量添加。也支持粘贴 `~/work/project` 路径。
- 顶部项目下拉框在窄面板中也始终可见，左侧保存最近项目，顶部提供可关闭的项目标签，`⌘P` 可搜索项目名称或路径，按 ↑↓ 和 Enter 切换。宽面板可拖动项目栏右边界调整宽度，双击边界恢复默认；顶部「项目管理」图标可收折项目栏，窄面板中则打开或关闭项目抽屉。宽度与收折状态保存在浏览器本地存储；存储不可用时仅在当前面板中生效。
- “管理”可固定或移除当前项目，右键项目条目也可管理失效的目录入口；移除不删除源代码或审查记录。重开会恢复上次的项目、所选文件和审查快照。

## 浏览和审查

打开 Git 项目后默认在 Summary 连续展示整批未提交改动，不必先创建快照。Summary 分为 Working Directory / 未暂存与 Staged Files / 已暂存，文件头可折叠并提供对应文件操作；文件标签按分区独立打开，同一部分暂存文件可分别查看 M、S 标签。提交编辑区位于 Summary，单文件标签集中显示差异；历史与快照也沿用连续文件结构。详见[Summary 与文件标签说明](../../docs/review-surface.md)。“工作区”按全部、已暂存、未暂存筛选；文件列表支持搜索。“提交历史”默认显示当前分支可达的最近 100 个提交（包含继承的历史），也可以切换到全部本地／远程分支，或勾选指定分支共同显示。共同提交只出现一次，列表标出分支 tip 和当前 HEAD；范围选择按项目记住，只影响显示，不会切换工作分支。点击提交查看相对第一父提交的差异，根提交也可查看；点击左侧分支比较 `HEAD → 分支`。

窄面板默认使用统一差异，宽面板默认并排；手动选择后会保留当前面板的视图偏好。右侧差异按真实新增和删除行对齐，支持并排/统一视图、语法高亮、折行、差异块导航、展开上下文和完整文件。默认仅显示改动周围 3 行上下文；大型差异每页最多 500 个对齐行条目。可用 `Alt+↑/↓` 或 `k/j` 切换上一个 / 下一个文件，`⌘R` 刷新。代码预览本身只读；显式 Git 操作的写入范围见下文。打开项目、刷新、同步、视图切换、Stage / Unstage 等常用操作使用图标，鼠标悬停可查看动作名称及适用的快捷键；快捷键不常驻显示。

工作区 Summary 的提交编辑区固定在顶部，滚动代码时仍可填写说明、关联任务并提交。短窗口里提交区限制高度并支持内部滚动；单文件标签、提交历史和审查快照集中显示审阅内容。

差异区右上角的「全屏审阅」会隐藏项目栏、提交历史和文件列表，让 Summary 或单文件差异占满插件视窗。文件标签及审阅操作仍可使用，点击「退出全屏」或按 `Esc` 返回；有弹窗时，`Esc` 先关闭弹窗。切换保留当前 commit、文件、代码阅读位置、评论草稿和已审阅状态，不重新加载已读取的差异。

点击旧／新代码行号旁的「＋」添加批注，在对应代码下方填写备注、问题或阻塞问题，保存后原位展示。Summary 中添加批注会保留连续审阅；全屏、并排和统一视图均可使用。下方「审阅批注」汇总当前视图的批注，点击位置可跳转到原始行，包括已折叠或其他分页的上下文。

首次批注或标记“已审阅”会自动保存所选比较范围的审查快照；Summary 中对未暂存／已暂存分区批注时，分别保存对应分区，不合并两侧。也可手动点击“保存审查快照”。若文件在查看后发生变化，会提示刷新，避免批注落在不同版本上。批注可删除，随审查记录保存在本机，并包含在 Markdown／JSON 导出中。同一面板内，不同行、旧／新侧、文件和审查快照的未保存草稿分别保留；关闭面板后未保存草稿不保留。保存期间暂时禁用编辑器，失败保留文字供重试。

标签上的 × 只关闭标签，项目仍在最近列表中；可从下拉框重新打开。每个项目独立保存进度。

从“审查记录”打开历史，或点击“返回工作区”查看新改动。快照不会随磁盘变化；对新改动需重新保存审查。导出 Markdown 包含状态和评论，JSON 包含代码快照；下载不可用时可复制文本。

没有 Git 的文件夹可以直接逐层浏览文件，选中文件查看代码并保存单文件审查。二进制文件只显示提示，可标记已审阅。

## 本地数据与限制

数据保存在 `${CODEX_HOME:-~/.codex}/local-review/reviews.sqlite`，可通过 `LOCAL_REVIEW_HOME` 修改目录。升级兼容 0.1 的审查记录并自动生成项目入口。各电脑数据独立，数据库权限 0600，不上传项目路径、代码或评论。

单文件默认上限 5 MiB，一次快照默认上限 50 MiB，最多 300 个文件。顶部“设置”可将单文件设为 1–20 MiB、快照总量设为 10–200 MiB，快照上限至少为单文件上限的两倍。设置保存在本机，重开后保留。超限提示会显示调整入口；单个大文件不阻塞其他文件预览，也不限制 Git 暂存操作。浏览改动按文件懒加载，其他大文件不会阻塞小文件预览。查找仓库最多深入 3 层、访问 1200 个目录、返回 100 个项目；不跟随目录符号链接，达到上限会提示。跨项目符号链接不会读取。

本版对齐项目打开、项目切换、工作区/历史浏览和差异审阅；暂不实现分叉后的 Git 合并、冲突解决、完整提交关系图、字符级差异或 AI 审查。提交历史展示最近 100 条，审查历史按项目分别展示最近 100 条。

在仓库根目录执行 `npm run install:local-review` 安装；更新时先执行 `git pull --ff-only`，再运行同一命令。该命令对应此目录的独立 `install.mjs` 入口，只安装或更新代码审查。验证：`npm test`、`npm run check`、`npm run test:local-review-ui`（需要 Chrome）。

参考：[Sublime Merge 官方入门文档](https://www.sublimemerge.com/docs/getting_started)、[差异上下文](https://www.sublimemerge.com/docs/diff_context)。

0.3.1 合并顶部项目工具栏，统一深浅主题与控件样式；项目、分支及文件名保持单行省略，悬停显示全文。干净工作区隐藏无效差异工具栏，并提供浏览提交历史和刷新入口。

## Stage / Unstage

工作区视图中，右侧提供当前文件的 Stage / Unstage。文件列表可勾选多个文件，再点击 Stage / Unstage 批量操作。“全选可见”只选当前过滤结果；按钮中的数字是本次实际操作的文件数，列表刷新会清空勾选。未暂存列表包含未跟踪的新文件。

在 Summary 中操作后保留原审阅位置：当前文件仍有改动时继续显示；整文件移出当前分区时由后继或前驱文件接替，不自动跳到另一分区。你主动滚动、点击或使用键盘导航后，自动位置补偿立即停止。单文件标签中完整 Stage / Unstage 会跟随同一路径到对应分区，局部操作优先保留当前侧的剩余改动；改动已全部消失时回到 Summary。

未变化的差异、搜索缓存及 Summary 滚动位置会复用；连续选择文件以最后一次为准。任务目录与提交准备在后台加载，不阻塞代码阅读或说明草稿；准备完成前提交按钮不可用。真正执行提交时暂禁修改说明，避免 Git hooks 等待期间的新文字被成功响应清空。功能覆盖、性能测量与边界见[流畅性 QA 报告](../../docs/review-fluency-qa-2026-10-16.md)。

Stage 使用 `git add --all -- <所选具体文件>` 暂存当前磁盘内容（含新增、修改、删除）；Unstage 使用 `git restore --staged --source=<当前 HEAD> -- <所选具体文件>` 只还原暂存区，保留工作区文件。无首次提交时仅移除相应 index 条目。暂存后仍可继续编辑文件，两种状态会分别保留。操作后自动刷新；历史提交和普通非 Git 文件夹不提供这些写操作。审查快照仅在下述内容核对通过后提供「Stage 已审阅文件」。

操作只响应用户在面板的明确点击，使用固定命令与字面文件路径，不接受任意 shell。列表过期、暂存区锁定、未解决冲突或子模块会给出明确反馈；不会自动删除锁文件、解决冲突、提交、推送或修改源文件。

参考：[git add](https://git-scm.com/docs/git-add)、[git restore](https://git-scm.com/docs/git-restore)。

## TAPD 任务联动提交

任务看板拥有 TAPD 凭据、任务来源与源码关键字缓存，并通过版本化的本机 MCP 接口提供提交上下文。代码审查只调用该接口，不读任务数据库、凭据文件，也不请求 TAPD。选择任务时，看板优先返回已有关键字，缺少时自动从 TAPD 获取并保存；无需切换到任务详情。接口由按需启动的看板进程提供，调用结束即退出，没有常驻监听服务。

提交编辑区显示当前分支，悬停可查看仓库路径，展开预览可查看完整提交信息和所有暂存文件；只提交暂存区，未暂存内容保持原状。HEAD、分支或暂存树变化时要求重新核对。支持首次提交，保留正常 Git hooks；拒绝空暂存区、冲突、detached HEAD 及进行中的 merge/rebase/cherry-pick/revert。只创建本地 commit，不 push、不改变 TAPD 状态。TAPD 远端关联仍需项目的源码应用和仓库 Webhook 接入；本地 commit 不代表 TAPD 已收到记录。

## 工作区常驻提交编辑区

提交编辑区位于工作区 Summary 的差异上方，无需打开弹窗；单文件标签中隐藏提交编辑区。尚未 Stage 时也可先编辑说明；Stage、Unstage、刷新或切换项目会保留各项目的说明草稿。选择已导入的 TAPD 任务后，审查插件向任务看板获取提交上下文，无需到看板逐项获取；说明为空时自动填入任务标题，已有说明不变。获取成功后直接显示完整源码关键字；点击「应用到提交说明」会用当前任务的完整关键字覆盖整段说明。应用时原样使用 TAPD 返回的信息，不另加标题或链接。提交预览与编辑区文字一致，提交时不再补写关键字；关联提交要求说明含有当前任务完整关键字的独立一行，否则需应用关键字或取消关联。切换或取消任务、关键字更新不会改动已有说明。获取失败保留草稿，显示原处重试入口，获取成功前禁止关联提交。完整 message 和暂存文件可展开预览，提交按钮明确提示暂无暂存改动。历史或审查快照不会显示提交编辑区。

TAPD 关键字旁、展开后的完整提交预览均提供复制图标。提交历史的 Summary 标题下也可一键复制完整 commit message（包含正文与空行）和完整哈希；悬停图标查看用途，复制结果在图标和底部状态栏提示。

关键字由看板保存；审查服务仅在内存中保留用户已经选择并预览的提交上下文，提交时核对关键字。仍要求用户明确点击提交，保留正常 Git hooks、HEAD/分支/暂存树校验，不自动 Stage、push 或修改 TAPD。

联动需要两个插件都支持提交上下文 v1。在仓库根目录执行 `npm run install:task-panel` 安装或更新任务看板时，会自动注册看板接口；也可以启动新版任务看板完成注册。单独安装代码审查时，普通 Git 提交仍可使用，任务关联处会提示安装或更新看板。详见[领域边界与通信协议](../../docs/task-commit-context.md)。

## 审阅与文件导航

已审阅是审查记录的状态，不会自动 Stage。工作区或未暂存范围的审查快照提供「Stage 已审阅文件」；执行时必须与当前磁盘内容和比较基线一致，内容变化则停止并要求重新核对。历史提交、分支比较及本地普通文件快照仍不提供此操作。暂存成功后回到同一文件的实时工作区，可继续 Unstage 或填写提交说明，原审阅记录保留。

差异栏上下按钮按左侧筛选后的文件顺序切换，首尾禁用，不循环；快捷键放在悬停提示中。改动块通过滚动浏览，原始 `@@` 标记改为「修改 / 新增 / 删除」和修改前后行号范围，保留真实代码行号用于评论。

## Git 工作台

顶部中央显示当前分支，点击展开可搜索的下拉列表，按本地／远端分组。中央按钮与下拉已加宽，列表增加可用高度，随窗口尺寸调整，便于查看长分支名和更多候选。选择一个分支后，显示该分支的操作，选择本身不会切换工作区。本地分支可选择「切换到此分支」或「从此分支创建新分支」；创建时显示起点，从该分支创建并切换，不自动继承 upstream。当前分支也能作为起点，列表底部不再提供独立的新建按钮。支持 ↑↓、Enter、返回、Esc 和外部点击关闭，表单、错误和重试均留在下拉里。右侧提供 Fetch、Pull、Push。

选择远端分支后可创建并切换到本地跟踪分支，默认使用远端后的分支名，也可修改本地名称；自动设置 upstream。同名本地分支已存在时，提供明确的切换本地入口，也可改名创建，不覆盖原分支。也可以选择「检出远端提交」进入分离 HEAD，不创建本地分支。远端列表使用已获取的引用，点击顶部 Fetch 可更新。切换前后会核对仓库和目标状态；未提交内容会被覆盖时停止，不自动 stash 或丢弃。下拉关闭后已开始的操作仍继续，失败后重开保留原选项以便重试。提交历史中切换工作分支后保留历史页，并选择新 HEAD（若它在当前显示范围内）；纯历史范围切换时保留仍可见的已选提交、差异滚动与评论草稿。外部切换分支后点击“刷新”同步。已勾选的分支被删除时显示提示，仍可重新选择。Fetch / Pull 主按钮直接操作当前跟踪目标；缺少明确目标时进入选择界面。Pull / Push 的下拉入口可选择远程和目标分支，显示 upstream 与本地领先 / 落后数量。Pull 仅快进，遇到分叉停止；Push 只推送选中的分支，不 force push、不附带 tags。使用本机已有 Git / SSH 认证。

差异区按 Sublime Merge 的操作层级提供「工作区」的 Stage All / Unstage All / Discard All，当前文件的 Stage / Unstage / Discard，以及每个 Git 改动块的 Stage Hunk / Unstage Hunk / Discard Hunk。全部操作覆盖仓库全部符合条件的文件，不受左侧搜索影响；Discard 只丢弃未暂存内容，保留暂存区，但会删除列出的未跟踪文件，执行前必须确认。局部操作使用后端 Git 生成的补丁，部分暂存文件在 Summary 的暂存 / 未暂存分区及对应 M、S 文件标签中分别执行局部操作。

所有写操作共用仓库锁，并核对预览状态。历史比较保持只读。操作执行后刷新分支、文件与提交编辑区，保留提交草稿。详见[交互与领域边界](../../docs/git-workbench.md)。
