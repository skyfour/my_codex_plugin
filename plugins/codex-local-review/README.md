# 本地代码审查

在 Codex 侧栏打开“本地代码审查”，或输入“打开本地代码审查”。这是人工 Review 面板，暂不接入 AI，也不要求远程仓库。

1. 填写本地项目绝对路径。Git 模式使用仓库根目录。
2. 选择全部未提交、已暂存、未暂存、两个本地提交/分支，或指定文件。指定文件支持没有 Git 的目录，路径每行一个。
3. 点击“创建审查快照”，从文件列表选择文件，左右查看旧、新代码。黄色表示同一行号的内容不同，插入行之后的行号不作自动对齐。长文件每页 300 行，可翻页。
4. 点击旧或新代码的行号，填写备注、问题或阻塞问题；完成文件检查后勾选“已审阅”。
5. 从右上角打开历史记录，或导出 Markdown / JSON。JSON 包含代码快照；Markdown 包含状态和评论。下载不可用时可复制导出文本。

项目只读，不写源文件、不提交、不调用远程服务。评论绑定创建时的代码快照；后续改动需新建审查。首次没有提交的仓库也支持新文件。二进制文件仅显示提示并允许标记已审阅。

数据保存在 `${CODEX_HOME:-~/.codex}/local-review/reviews.sqlite`，可通过 `LOCAL_REVIEW_HOME` 修改目录。升级保留数据，各电脑数据独立。数据库权限 0600；不要将审查数据库或包含代码的导出放入公共仓库。

单文件最多 1 MiB，一次最多 300 个文件、10 MiB；超限会明确报错。跨项目符号链接不会读取。暂不支持目录递归选择、自动合并审查快照和 AI 审查。历史下拉展示最近 100 次审查，旧记录仍保存在数据库中。

安装、升级均在仓库根目录执行 `node scripts/install.mjs`。验证：`npm test`、`npm run check`，原生宿主模拟浏览器测试在根目录运行 `npm run test:local-review-ui`。
